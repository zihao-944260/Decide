# BaseTabBar

底部悬浮胶囊导航（形态对齐用户 2026-11-17 给的参考图）：白底通栏胶囊 + 每项「图标 + 文字」，
选中态是**一颗会滑的浅灰内衬滑块**（`$color-fill`）+ 主色 semibold 文字 + `-active` 实心图标。
`position: fixed` 悬浮在页面之上，**外层不画底色**（用户 2026-11-18 口径：要发布按钮那种效果，
让列表透出来）—— 看得见的只有胶囊那颗白底圆角盒，列表从它左右两侧和下方安全区那条带里穿过。
代价写在下文「安全区与置底浮层」：它不再占 flex 空间，滚到底的让位必须由页面自己在滚动内容尾部垫高。

三项顺序 = `TABBAR_ITEMS` 数组顺序：首页 / Great Ideas（中间）/ 我的。

## Props

| prop | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `active` | `TabBarKey`（`'home' \| 'ideas' \| 'mine'`） | 必填 | **本页是哪一项**，不等于「高亮哪一项」（见下） |

## 高亮为什么归 store 而不是 `active` prop

微信的 tab 页是常驻实例：切 tab 不销毁页面，而每个页面传进来的 `active` 永远等于它自己那一项。
滑块要「从旧位置滑到新位置」，就必须有一份两个页面都能观察到的状态 —— `src/stores/tabbar.ts`
（`active` + `prev` + `go()`）。组件 setup 期先 `go(props.active)` 认领自己：
冷启动直达非首页 tab 时 store 还停在默认项，这一步把它掰正，滑块不会停在别的格子上。

`prev` 只服务一件事：**第一次**进入某个 tab 页时它的胶囊是刚挂载的，没有可继承的旧位置，
组件把滑块起点摆回 `prev` 那一格，`onMounted` 后 32ms 再写目标格，把同一段滑动补跑出来。

## 滑块与果冻

内衬不是「每项各自的背景」，而是胶囊里唯一一颗绝对定位节点：

- **槽位** `.base-tabbar__slider`：宽 `100 / 项数 %`，位置只靠 `translateX(格数 * 100%)` 表达
  —— 增删导航项不需要改任何样式；`transition: transform $duration-tabbar-slide $ease-tabbar-spring`，
  bezier 第二控制点 1.25 >1，所以滑过头再回落，但过冲峰值只有 1.0204。
- **本体** `.base-tabbar__jelly`：胶囊形（`border-radius: $radius-round`，不是固定圆角档位），
  `@keyframes` 走一段**衰减振荡**：22% 顺行进方向拉长 1.05 → 52% 收回 0.978 → 68% 落点压扁鼓起
  0.94×1.056 → 85% 反冲 1.024 → 100% 停。

形变的节拍不是随手排的：`$ease-tabbar-spring` 的过冲峰值数值解出来落在时长的 **67%**，
所以「拍在墙上」那一帧就放在 68%。位移与形变对不上拍，是上一版「生硬」的一半原因；
另一半是幅度 —— 上一版 26% 一次就拉到 1.22 / 压到 0.8（±22%），现在是 ±5~6%，
而且后一次摆动比前一次小，这才是果冻，不是抖动。

两层必须分开写：**transform 只有一个**，位移和形变落在同一个节点上会互相覆盖。
重启 keyframes 靠 `--odd` / `--even` 两个类轮换（两段内容逐字相同、只是动画名不同）——
小程序没有 DOM，改不动 `animation-name` 也强制不了重排，换名是让同一段形变再播一次的唯一办法。
`jellySeq === 0` 时不给动画类，否则首帧会凭空抖一下。

**「色块冲出导航」是靠几何解决的，不是靠裁剪。** 滑块离胶囊沿的距离 = 内衬 −（过冲 + 形变半宽），
三项都算得出来：静置内衬横向 13.56px，过冲最多 4.85px（bezier 峰值 2.04% × 2 格 × 槽宽 118.9px，
实测最狠 7.9px），拉长多吃掉 2.3px（92 × 5% ÷ 2）—— 而拉长发生在 22%（还在半路），
过冲在 67%（正在压扁、变窄），两者不同时出现。所以实测最近也只到离沿 9.6px。
纵向同理：静置 7.3px，鼓起吃 1.4px，实测最近 5.8px。
胶囊上的 `overflow: hidden` 因此只是兜底（万一以后把预算调爆），正常动效里它一次都没裁到东西。

内衬加厚把胶囊从 112rpx 撑到 124rpx：色块四周的白边要变宽，可色块还得把 81rpx 的图标+文字包住，
两头一起算，外框只能跟着长（112rpx 下纵向内衬一旦超过 15rpx，文字就顶到色块沿了）。
带高变了，置底浮层的让位间距同步从 `$space-2` 抬到 `$space-3`。

规格全在 `tokens.scss`：`$tabbar-pill-inset-x/y`（本体在槽内的内衬，同时是形变预算）、
`$tabbar-height`、`$duration-tabbar-slide`、`$ease-tabbar-spring`。

## 为什么不是原生 tabBar

微信原生 tabBar 由客户端在页面之外绘制，`pages.json` 只能改颜色/文字/图标，画不出悬浮胶囊与选中内衬。
所以：

1. `pages.json → tabBar` 段**保留不删** —— 它决定哪些页面是 tab 页，`switchTab` 才可用；
2. 同一段加 `"custom": true`，并在 `src/custom-tab-bar/`（uni-app 原样拷进产物根目录）放一个 **0×0 空壳组件**：
   它不画任何东西、不吃点击，唯一作用是把原生条整块关掉并把视口整块还给页面；
3. 数据源是 `src/constants/tabbar.ts` 的 `TABBAR_ITEMS`，与 `pages.json` 的 `tabBar.list` 一一对应，改一处必须改两处。

**为什么不用 `uni.hideTabBar()`**（Skyline 渲染，2026-11-17 模拟器实测）：
hideTabBar 只擦除原生条的绘制、不归还它预留的那条带子 —— 收起前后 `windowHeight` 恒为 762
（`screenHeight` 844），胶囊底下始终露出 82px 窗口黑底，且那条带在 webview 之外，页面自己画不到。
`custom: true` 之后实测 `windowHeight` = 844、黑底消失。

**为什么不让原生自定义条来画胶囊**：把 `src/custom-tab-bar/` 写成真正的胶囊后实测两件事——
它默认贴在屏幕顶部（要自己 `position: fixed; bottom: 0`），且它是覆盖在页面之上的浮层，
会把首页发布 pill 整个盖掉；它的 `selected` 也不会跟着 tab 切换更新。
所以导航本体放在 Vue 侧（同时才能吃 SCSS 设计 token），原生侧只留空壳。

冷启动没有原生条闪现（自定义条从未被绘制），也不需要 `hideTabBar` 那一次重排。

## 安全区与置底浮层

tab 页上 `env(safe-area-inset-bottom)` = 34px（模拟器实测）。胶囊本体高 `$tabbar-height`，
离屏底 `calc(#{$tabbar-bottom-gap} + env(safe-area-inset-bottom))` —— 安全区由导航自己吃，
页面不需要再为它垫任何东西。

**导航不再占 flex 空间，所以「让位」这件事分成两条完全不同的路：**

1. **钉在页底的浮层**（首页发布 pill、我的页退出登录 pill）让出「胶囊带 + 安全区」，
   统一走 `mixins.scss` 的 `above-tabbar($extra)`，不要各自写 `bottom: 0` + `safe-area-bottom`。
   带高 `$tabbar-band = $tabbar-height + $tabbar-bottom-gap`，规格全在 `tokens.scss`。
2. **滚动列表**不能靠视口让位 —— 视口必须一路铺到窗口底，列表才透得出来（就是这条需求的目的）。
   让位改垫在**滚动内容尾部**：`PlanList` 的 `float-clearance` 在末项之后插一个
   `.plan-list__float-space`，高 `$tabbar-band + $space-3 + $fab-size + $space-2` + 安全区。
   这是 #45 定下的口径（浮层不压视口，垫内容），跟首页 FAB 的收/放不改变视口高是同一件事。

Skyline 没有 `pointer-events`，悬浮盒会吃掉它**盒子覆盖范围**内的点击。外层盒是整宽
（0–402），但列表盒内缩 `$space-3`（12.9–389.1），所以左右两条透明侧条压根不在列表上方；
真正与列表重叠的区域就是那颗不透明胶囊 —— 藏在胶囊底下的卡片本来就看不见，摸不到不算回归。

## 悬浮定位实测（2026-11-18，iPhone 17 模拟器 402×874 —— 设备从 iPhone 14 换过，数值按新屏宽重测）

| 项 | 值 |
| --- | --- |
| `.base-tabbar` 外层盒 | 402.0×66.5，`top` 765.0 / `bottom` 831.5，离屏底 42.5（= 16rpx gap + 34 安全区）—— 盒高等于胶囊高，外层没有多余的带 |
| 胶囊 | 367.7×66.5，`left` 17.2 / `right` 384.9 |
| 滚动视口 | 首页 `.plan-list` 376.3×780.0，`bottom` 874.0 = 窗口底（**改 fixed 前视口底比窗口底高一条带**）；我的页 874.2 |
| 尾部让位垫 | 高 182.0 = 276rpx(147.9) + 安全区 34.1，逐项对上公式 |
| 滚到底末卡底边 | 644.8（首页）/ 645.0（我的页）→ 距胶囊顶 **120.0**、距 pill 顶 127.8、距发布按钮顶 60.1 |
| 滚到底内容尾（页脚底 / 让位垫顶） | 692.0 → 距胶囊顶 **73.0**、距发布按钮顶 **13.0**（= 公式里那格 `$space-2`，无页脚时末卡就落在这里，是最小保证间距） |

「滚到底」那一行是算出来的不是截出来的：automator 对 Skyline 的 `scroll-view` 调 `scrollTo`
不报错但也不动（截图逐像素相同），所以取静置时的内容坐标与视口底，按
`maxScrollTop = 内容尾 − 视口底` 平移 —— 两端都是实测盒，只有「滚到底时内容尾贴视口底」这一条
是 scroll-view 的固有行为。手指滚到底的最终观感以模拟器验收为准。

## 动效实测口径（2026-11-18，iPhone 14 模拟器 390×844，三 tab 形态）

> 这一张是**动效**（滑块位移/形变/包络）的实测，采于改成 fixed 悬浮之前、设备还是 iPhone 14；
> 盒尺寸随屏宽变（14 的 390 → 17 的 402），形态与结论不变。布局与让位的数值以
> 上一节「悬浮定位实测」为准，别把两张表的 px 混着用。

| 项 | 值 |
| --- | --- |
| `windowHeight`（三个 tab 页） | 844（hideTabBar 方案下是 762） |
| 胶囊本体 | 356.8×64.5，`left` 16.7 / `right` 373.5（= 124rpx 高，圆角 32.25px） |
| 滑块槽位 | 宽 118.9px（356.8/3） |
| 滑块本体静置 | 92.0×50.0，三格 `left` 实测 30.1 / 149.1 / 268.1（圆角 25.0 = 32.25 − 7.25，两层弧线同心） |
| 白边（色块离胶囊沿） | 横向 13.6px（像素扫描 13.4~13.7）、纵向 7.3 / 7.2px；中间格左右各 132.4 / 132.1，居中 |
| 滑动逐帧（动效放慢到 3s，40 帧） | 我的→首页 `left` 236→…→30→**27（过冲）**→28 收住；首页→我的 `right` 154→…→360→**364（过冲）**→362 |
| 果冻逐帧（同一段） | 92×50 → 96×48（拉长）→ 92×50 → 87×53（落点压扁）→ 94×49（反冲）→ 93×49 收住 |
| 连跳四次的重播 | 四个方向各一跳，每一跳都重播同一段形变（尺寸序列逐帧一致）—— 换名重启有效 |
| **全程包络 vs 胶囊沿** | 慢放：左余 10.4 / 右余 9.6 / 上余 5.9 / 下余 5.8；真速 6 跳：左 13.4 / 右 7.3 / 上 6.0 / 下 5.4 —— **一次都没贴到边** |
| 发布 pill 底边 → 胶囊顶边 | 12.5px（`above-tabbar($space-3)`） |
| 点胶囊切 tab | `switchTab` 生效（空壳不拦点击） |

采样口径：automator 每帧取 `Element.offset()` / `Element.size()`，一次往返约 94~150ms。
500ms 的动画抓不满整段，所以包络那一行把 `$duration-tabbar-slide` **临时**改成 3000ms 再测：
形变幅度与过冲距离都是时间的函数、与时长无关，慢放只改变采样密度、不改变空间包络；
测完改回 500ms 并重新构建验证过（产物 CSS 为 `animation:… .5s linear`）。
rect 查询会反映动画中的 transform，这一点由逐帧位移/尺寸连续变化证实。
